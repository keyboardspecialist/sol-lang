# P4.4f1c — ordinary scalar callee-chain handoff

**Status snapshot:** 2026-10-19 local / 2026-10-20 UTC · **Bounded implementation
and evidence:** accepted · **Exact validation union and supplementary checks:**
complete · **Feature publication:** `24e2d16` pushed · **Documentation review, Astra

P4.4f1c lifts the ordinary-callee-leaf restriction beneath the existing f1b
predicate-call form. Independent final technical/evidence and documentation reviews
approve this bounded implementation, its complete 506-key-per-mode evidence, and
supplementary checks. The feature was committed and pushed; Astra publication
readiness and coordinator integration gates are closed. This is not broad P4.4
closure, R-AUTH closure, full-suite acceptance, or speed success. This handoff records
the closed continuation report and reviewed ledgers; it does not poll live receipts.

## Reviewed implementation boundary

The predicate edge remains exactly the f1b shape:

* An INSTANCE-owned, non-refinement, ALWAYS `requires` body contains exactly one
  direct FUNCTION call. The call is `DIRECT_INTERNAL`, has one owned plain `Int64`
  argument, and produces the predicate's plain `Bool` VALUE through the existing
  authenticated normal-edge parameter.
* Below that predicate target, each reachable ordinary callee has one owned plain
  `Int64` parameter, a plain `Int64` or `Bool` VALUE result, and an empty closed
  effect row on image, signature, and outgoing invokes. This subordinate ordinary
  signature does **not** widen the predicate ABI to `Int64` results, Bool/Unit
  arguments, Unit call results, or multiple arguments.
* The complete reachable image, owned predicates, snapshots/projection paths, and
  cleanup remain within plain `Int64`/`Bool`/`Unit` recipes. The whole-target checks
  include dead blocks. Text (including panic detail), aggregates, refinements,
  function handles, richer snapshot/drop forms, and unsupported terminators remain
  rejected even when not executed.
* Ordinary image-call cycles and recursive SCCs are allowed. Any owned-predicate
  `INVOKE` anywhere in the reachable closure—including dead predicate blocks—or a
  mixed image/predicate cycle rejects the **whole** closure. A nested predicate DAG
  is rejected too. Existing call-free scalar `ensures` and `old` behavior remains;
  this does not add calls in ensures/refinements or another predicate location.

The exact immediate predicate join, complete owner authentication, source/linkage/
operand/edge/cleanup joins, ordinary catalog rows, function preflight, failure
preflight, and emitter consumers are retained. All convention rows are authenticated
before classification. After existing Kahn and per-edge SCC/depth metadata is
finalized, the closure walk reuses the already allocated indegree and queue arrays
as visited/worklist, marks on enqueue, and is bounded by actual authenticated V/C
and checked catalog work sizing. The build wire path has its existing 256-function
cap; that is not a universal bound on the shared catalog accessor. The walk adds no
allocation request, CPU-work meter, cached authentication, recursive C graph walk,
graph-row mutation, emitter/ABI/header/IR/schema change, or production export.

Runtime transport is unchanged: ordinary calls consume real frames, the inline
predicate evaluator consumes none, and per-activation locals/temporaries/snapshots
remain distinct. Step exhaustion code 6 precedes depth code 7. Depth is decremented
before pending-packet inspection; a callee's primary code/site remains pending
through predicate failure cleanup and is not converted into a false predicate or a
second caller requires failure. At the depth boundary, predicate-local exhaustion
is a `PREDICATE_CALL` failure; exhaustion entering an ordinary helper is an
`IMAGE_CALL` failure returned through predicate `FAILURE_CALL` as pending. Pending
cleanup consumes no extra steps.

## Source-backed execution and compatibility

The new fixture has one genuine `@entry launch`, returning 5 through
`launch -> core -> helper(5) -> other(4) -> helper(4) -> terminal(4)` at maximum
source depth 6. Ordinary `helper`/`other` calls form the admitted two-node SCC.
Separate failure roots preserve caller requires 13, callee requires 13, arithmetic
3, and callee ensures 14; recursive helper snapshots overlap. Expected source/P2/P3
paths, actions, snapshots, failure sites, and provenance are prepared before
interpreter confirmation, catalog queries, or backend execution. Only `launch` is
a genuine `@entry`; selected failure roots use the existing guarded raw-function
test alias as `INTERNAL_FIXTURE` roots, without fabricated entry metadata or source
writes. Source-derived traced step points are `n=8`, `m=27`, and `S=115`; these are
source-row expectations, not interpreter/backend step-unit equivalences. The
existing bounded source/P2 walker is extended only for the required checked
subtraction/equality and their source sites/operands. It constructs complete ordered
actions, activations, snapshots, and provenance before interpretation or backend
execution; fixed trace/action/visit/frame capacities remain unchanged, and an
overflow fails rather than truncating or filtering evidence.

For the default-limit semantic/fault profiles, one same-instance witness executes
raw failure -> genuine `launch` success/reset -> the same raw failure. It does not
write packet/step/depth state or introduce a synthetic reset export; only the
existing saved-and-checked trace cursor may be cleared. The source expectations
distinguish predicate-local depth exhaustion from an ordinary callee's pending
depth failure and keep step-6 precedence over both.
