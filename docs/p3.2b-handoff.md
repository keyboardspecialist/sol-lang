## Objective

Extend `SolMirRuntimeValues` with independently validated, target-parameterized
allocation plans for current `Text` and aggregate representations. Freeze checked
sizing, zero-length `Text`, cumulative allocation-count/requested-byte quotas, and
the distinction between allocation-limit rejection and physical allocator refusal.

P3.2b does not add a physical allocator, pointer encoding, runtime storage,
ownership traversal, move/drop, deep copy, equality execution, cleanup edges,
host-result transfer, or Wasm lowering.

## Approved Design

Add one same-ID `SolMirRuntimeAllocationPlan` per concrete recipe with these kinds:

- `NONE` for uninhabited, zero-sized, scalar, callable, and capability layouts.
- `FIXED_OBJECT` for inhabited nonzero product/sum layouts and wrappers that inherit
  those layouts.
- `TEXT` for Text layouts and wrappers that inherit Text layout.

Canonical `NONE` plans have zero object bytes and alignment one. Fixed and Text
plans copy exact object size and alignment from the authenticated P2 layout. Plans
describe only the outer object; they do not recursively include child allocations.

Text always requests its fixed header object. Length zero requests no payload
allocation. Nonzero length requests one additional byte-aligned payload allocation
of exactly that length. Length and each requested object must fit target width and
`max_object_bytes`.

Runtime quotas are separate from compiler-owner construction limits. They count
cumulative successful allocation requests and requested bytes; destruction never
restores quota. Checked preflight is allocation-free, O(1), non-mutating, and uses
`uint64_t` overflow checks. It returns:

- `SUCCEEDED` when exact demand plus current usage fits.
- `INVALID_ARGUMENT` for malformed owner/request/current-usage inputs.
- `ALLOCATION_LIMIT` for target-size, arithmetic, count, or byte-limit rejection.
- `ALLOCATION_FAILED` only as the frozen outcome for later physical allocator
  refusal; the pure quota checker never returns it.

Outcome-to-failure mapping uses the existing P3.1
`SOL_MIR_RUNTIME_FAILURE_ALLOCATION_LIMIT` and
`SOL_MIR_RUNTIME_FAILURE_ALLOCATION_FAILED` codes. P3.2b adds no failure sites or
cleanup edges.

## Expected Census And Coverage

For the frozen E6 Wasm32 fixture, expect 21 plans: eight fixed aggregate objects,
one Text plan, and twelve `NONE` plans. The Text header is eight bytes aligned to
four, and fixed aggregate object bytes total 92.

Add a focused fixture for zero-sized/uninhabited aggregates, callable/capability
layouts, and scalar/Text/aggregate wrappers because E6 does not cover all inherited
classification cases.

Malformed coverage must include plan recipe/kind/size/alignment/count/capacity,
usage, null/wrapping/predecessor-alias ranges, operation-plan cross-aliasing,
predecessor mutation, allocation failure at either persistent arena, validator
scratch failure, and zero-write rendering of malformed owners.
