This document is a historical, pre-implementation design snapshot captured at
baseline commit `1aed2f7` (`define allocation-free runtime equality plans`). It
preserves the approved P3.2f design; it does not describe current implementation
state or work cursor. `TODO.md` is the live and sole authority for status and
execution order.

- At capture, P3.2a-P3.2e were complete, including static allocation,

- At capture, the cursor was P3.2f. Parent P3.2 and P3 were incomplete.

## Objective

Extend `SolMirRuntimeValues` with one same-ID static host-result plan per
recipe. These plans close the frozen-profile value-operation contract by
describing which E3-safe host-result views can be checked and copied into a
fresh, owned represented-value tree. They do not execute a host call or expose
a host adapter API.

P3.2f does not add a production executor, runtime storage or allocator,
physical ABI or pointer encoding, host adapter, authority grant or preflight,
failure records/sites/masks, cleanup lowering, MIR changes, interpreter changes,
or Wasm lowering. P3.3 owns cleanup, panic, failure placement, and precedence;
P3.4 owns capability/trusted-host ABI, authority, adapter, and host-call
integration.

## Approved Design

Host-result-plan classifications are `UNREACHABLE`, `FORBIDDEN`, `INT64`,
`BOOL`, `TEXT`, `UNIT`, `OPTION`, and `RESULT`.

- `UNREACHABLE` remains distinct from `FORBIDDEN`; uninhabited recipes cannot
  produce a live result, while forbidden recipes are outside the E3 safe
  data-only result vocabulary.
- Scalar leaves have their represented value copied directly. `UNIT` is an
  initialized logical value and has no object allocation.
- `TEXT` copies a checked length-delimited byte view into a newly owned header
  and, only when nonempty, a newly owned payload.
- `OPTION` and `RESULT` copy only the selected semantic case and recursively
  copy its payload where present. Tags, inactive payload, padding, and
  representation bytes are not read or copied.
- Recursive eligibility is E3-only: an eligible recursive result is composed
  solely from the approved `Int64`, `Bool`, `Text`, `Unit`, `Option`, and
  `Result` host vocabulary. Products, arbitrary sums, wrappers, callables,
  capabilities, and any composite outside that closure are forbidden. This is
  independent of `Copy`, equality, operation-demand bits, imports, and runtime
  allocation demand.

The host-result requirement closure is reconstructed from authenticated P3.1
host requirements and their concrete result recipes. Every reachable host result
must have the corresponding same-ID plan and must be eligible under the E3-only
closure; a demanded result with an unreachable or forbidden plan rejects the
owner transactionally. Plans do not duplicate recipes, layouts, digests, imports,
host requirements, variants, allocation plans, ownership edges, copy plans, or
equality plans.

The input is a finite borrowed host view. It may refer to callback argument
views or to other host-owned storage and is never adopted: the resulting tree is
freshly owned, never aliases host storage, and P3.2f never frees, mutates, or
takes ownership of host memory. A copied text payload and every selected nested
sum payload are independently owned. The host must keep the borrowed view alive
for the modeled transfer; no lifetime or adapter ABI is introduced here.

Before staging, complete shape preflight validates the full selected recursive
view: kind/plan correspondence, valid text pointer/length pairs, valid
`Option`/`Result` case and payload presence, target/object/length arithmetic,
and every recursive child. It does not stop at an earlier usable value. Preflight
uses depth 256, at most 1,048,576 nodes, and at most 4,000,000 work steps; exact
fit succeeds. It computes the complete aggregate allocation demand with the
P3.2b allocation plans and quota checker. It performs no allocation, mutation,
publication, or quota charge.

After successful preflight, staging allocates and copies privately in source
order. Each successful request is charged immediately under P3.2b cumulative
request/byte quotas; a refused request is uncharged. The staged owned root is
published exactly once only after all fallible work succeeds. On staging failure,
the destination remains unavailable, host storage is unchanged, initialized
staged descendants are rolled back through the P3.2c ownership postorder, and
successful quota charges are not refunded. No path adopts or frees a host view.

The finite test-only model returns `SUCCEEDED`, `INVALID`, `LIMIT`,
`ALLOCATION_LIMIT`, or `ALLOCATION_FAILED`. Malformed host shape, a plan/kind
mismatch, or an ineligible class is `INVALID`; depth/node/work exhaustion is
`LIMIT`; aggregate quota/target/object/overflow rejection is `ALLOCATION_LIMIT`;
and modeled allocator refusal is `ALLOCATION_FAILED`. These outcomes specify the
model only. P3.2f introduces no production result API, failure record, site,
mask, or precedence rule.

## Resumption Slices

Implement these sequentially and keep each slice focused:

1. Add host-result-plan API types, arena, limits, usage, transactional
   construction, E3-only recursive classification, and host-requirement closure.
2. Add independent reconstruction/validation with exact checked bytes, work,
   and scratch metering; authenticate full ranges and every raw,
   cross-arena, and predecessor alias relation before dereference.
3. Add the test-only borrowed-view transfer model: complete preflight,
   P3.2b aggregate demand/quota, private staging, rollback, one-time
   publication, non-refunding quota, and fresh-ownership behavior.
4. Add canonical buffered rendering, determinism and malformed-owner zero-write
   tests; update status documentation only after implementation review passes.

Do not advance `TODO.md` between these slices. They are interruption boundaries
inside one checkpoint, not independently completed roadmap items.

## Construction, Validation, And Rendering

Construction is transactional. Independent validation reconstructs every
host-result plan and the complete demanded-host-result closure without calling
construction helpers. It verifies exact same-ID correspondence, classifications,
complete arena consumption, and all raw-range, cross-arena, and predecessor
anti-aliasing relationships before dereferencing. Construction and validation use
exact checked bytes, work, and scratch metering; persistent-arena and
validator-scratch allocation-fault selection remains deterministic.

Canonical buffered rendering declares `host-result-plans=true` and
`host-result-execution=false`, and emits stable digest-keyed classifications and
the closed host-result requirement relation. It must not expose raw IDs,
pointers, capacities, paths, allocator state, host storage, or transferred
contents. Rendering a malformed owner writes zero bytes.

## Expected Census And Coverage

The fixed E6 Wasm32 fixture retains 21 recipes, allocation plans, ownership
plans, copy plans, equality plans, and now host-result plans; nine variants; 12
ownership edges; 10 copy imports; 17 drop imports; five equality imports; 52
P3.1 imports; 29 P3.1 sites; and four host imports. Existing resource censuses
remain authoritative. Measure and freeze the host-result class distribution and
its byte, build-work, validation-work, and scratch censuses during
implementation rather than inferring them here.

Add focused fixtures for every class; every E3 scalar and recursive shape;
empty/nonempty text; `Option`/`Result` success and residual cases; recursive
eligibility; forbidden aggregate/wrapper/callable/capability cases; and host
requirements whose concrete result is ineligible. The model must cover borrowed
argument aliasing and unrelated host storage, while proving that the successful
destination is fresh and host storage is never freed or adopted.

Also cover malformed kind/payload/text shapes, complete preflight before any
allocation, exact depth/node/work boundaries, P3.2b exact/overflowing aggregate
quota, target and object limits, allocator refusal at every request, postorder
rollback, one-time publication, non-refunded quota, owner limits, malformed
mutations, raw and cross/predecessor aliases, persistent and scratch allocation
faults, determinism, and zero-write rendering of malformed owners.
