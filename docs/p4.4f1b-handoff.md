## Approved execution boundary

The addition is actual execution of one narrow source-call-leaf shape in a
represented Wasm module:

* The caller contains an INSTANCE-owned, non-refinement, ALWAYS `requires` body
  whose predicate is one direct FUNCTION CALL. Its body has exactly one `INVOKE`,
  producing the predicate Bool through the authenticated normal-edge parameter.
* The call target is an exact `DIRECT_INTERNAL` callable with one owned, plain
  `Int64` parameter, a plain `Bool` value result, and an empty materialized effect
  row. There is no receiver, host/table target, writeback, or new call ABI.
* The target is a source-call leaf across its complete authenticated image and all
  its predicate bodies, including dead/unexecuted blocks. Its locals, temporaries,
  image/predicate values and snapshots stay within plain `Int64`/`Bool`/`Unit`
  recipes. The gate excludes Text, aggregates, refinements, function handles and
  panic-detail production; it does not rely only on the signature or executed path.
* Existing scalar call-free helper `requires`, `ensures`, and scalar `old` snapshots
  remain usable and retain their prior checks. Unit is only existing bookkeeping,
  not a newly admitted call argument/result. The caller continues through its normal
  ownership, snapshot, cleanup, and validation gates.

This does not admit Bool/Unit call signatures, zero or multiple arguments, other
predicate locations, multi-call predicates, non-leaf callees/recursion, richer dead
blocks, represented values, methods, callbacks, panic Text, or other new terminators.
It changes no schema, wire/provenance version, public header/API, production export
surface, host/E6 integration, P4.5, or P5. P4.4 remains unchecked.
